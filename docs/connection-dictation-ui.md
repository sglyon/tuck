# Notion connection and voice-note interface

The UI keeps the established cool porcelain Operate surface. Notion Settings now starts with Connect with Notion, an explicit browser handoff, cancellable pending state, connected workspace metadata, and destination search. Builds without a configured authorization relay say so and disable sign-in. Manual tokens and direct database entry are disclosed under Advanced connection. Connection responses contain metadata only; credentials stay native.

What to publish selects Recap, My notes, and Action items. All three match the previous default publication. Turning off the last section also turns off automatic publishing and explains why. Selected text goes to the chosen Notion database; the authorization relay does not receive notes. Automatic publication remains an explicit preference and is disabled without credentials, a destination, or any selected content.

Dictate a note checks microphone/local speech readiness before creating or starting anything. It flushes current drafts, creates a dictation document, and uses the existing recording lifecycle with microphone true and computer audio false. A start failure leaves the draft selected for retry. Active voice notes show actual recognized segment text before the optional short note editor. After stopping, the plain editable Notes document offers Copy text. Completed or interrupted voice notes also expose Original speech above the editor, retaining actual recognized words independently of typed or later-edited notes. Copy original speech includes save guarding and explicit clipboard failure/retry. Clipboard and save failures retain the document and expose recovery. Voice notes have no recap, enhancement, publication, assistant, or system-audio controls. The backend additionally enforces microphone-only capture and suppresses automatic recap/publication.
