# Library loading interface

The desktop App uses `bootstrap_library`, never the compatibility full `bootstrap`. Startup transfers one page of 50 metadata-only headers plus settings, engine state, accounts and a global overview. `get_meeting` opens the selected ID directly, including IDs absent from the loaded page. The browser preview implements the same actions with its illustrative local data; it does not qualify native payload or memory performance.

Headers and complete details have separate ownership. The detail cache retains selected, active, unsaved note/recap/correction and operation owners plus five recently used idle meetings. Writes retain their existing per-meeting queues and editor flushing. Detail request versions prevent an older read from replacing an incoming event or pending edit. Late selected-detail responses stay attached to their meeting, and late filter pages cannot populate a new scope. Source navigation resolves an off-page meeting before highlighting its segment. Successful edits refresh header metadata and global counts; cached bodies are not used as a library index.

Sidebar text search, starred selection and organization scope use server queries across all meetings. Overview supplies global counts and up to 200 sorted suggestions per facet; omitted choices are disclosed and accept a typed exact name. Library answers continue using full-library retrieval and their returned citation allowlist. The task inbox uses `list_task_page` with server scope, completion filtering and Load more, independent of the header/detail cache. Completion responses trigger the latest selection's refresh, so toggling Show completed during a slow write cannot restore an old filter.

Background recording updates preserve the loaded header chain and open selection. Overview/scoped count refresh is bounded and throttled during speech; exact transcript-query membership can refresh its result page. A changed cursor is handled when Load more is requested: the first page is loaded quietly, the user sees an explanation, and the open document stays selected. Restore reinstalls bootstrap metadata and reapplies the current filter selection.

Compact screens keep expanded filter controls in a separate scroll region with at least 140px for conversation results and error recovery. Loading uses restrained status copy; failures retain a reachable Try again action. The visual world, footer and one-pane navigation remain unchanged.

- The final root verification passed all 30 browser tests. Before that final run, all six focused loading regressions passed after the containment and failed-query recovery corrections. The compact-screen regression checks a visible retry action, a results region at least 140px high, no horizontal overflow, successful retry and clearing a failed query back to the original selection.
- The five large-library behavioral tests cover native lean startup/no compatibility-bootstrap calls, all/starred paging, full-library query/facets, off-page evidence/task owners, 75 global tasks beyond the first 50 headers, delayed reads, retry/stale-cursor behavior, retained older rows after background speech refresh, cache eviction/edit ownership, incoming segment events and a delayed completion/Show completed race. A safety regression verifies restore retains a current query. Older native mocks use a test-only compatibility adapter; the dedicated large-library fixture rejects eager bootstrap.
- `loading-*-{desktop,mobile}.png` in `.impeccable/review/` contains one 22-image desktop/390px batch, followed by five affected-state confirmation captures.
